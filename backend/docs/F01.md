O caminho de saúde permite acompanhar o MVC: rota → Controller → Model → consulta MySQL → View. A execução real dessa consulta, o rollback e a indisponibilidade SQL serão verificados nas etapas seguintes.

### Correção da configuração

A validação anterior verificava apenas o prefixo da URL. Foram reproduzidas configurações aceitas indevidamente sem servidor, sem database ou com porta inválida.

Agora a URL é interpretada pelo SQLAlchemy antes de montar uma conexão. Ela exige driver `mysql+pymysql`, servidor e nome do database explícitos; uma porta informada deve estar entre 1 e 65535. Omitir a porta mantém o padrão MySQL 3306. Outros drivers, URL ausente e configurações incompletas são recusados, sem fallback para banco local.

Os controles existentes de TLS e timeout permanecem em variáveis próprias: parâmetros da URL não podem desativá-los ou substituí-los. Variáveis exportadas no processo continuam tendo precedência sobre `.env`. Mensagens de validação omitem os valores de entrada, e `get_settings()` mantém o erro público sanitizado.

### Dados e inicialização

O novo teste de startup impede conexões SQLAlchemy e chamadas ao bootstrap administrativo enquanto inicializa o ciclo de vida ASGI, abre Swagger/OpenAPI e verifica uma requisição sem token. A inicialização não tenta criar contas, conectar ao banco ou carregar seeds.

Isso se refere à inicialização da aplicação FastAPI. Os comandos existentes `scripts/dev.py` e Compose executam Alembic antes de iniciar o servidor; suas migrations técnicas não contêm cadastros. O modo **opcional** de MySQL em contêiner importa o DDL autorizado somente em volume vazio. O cadastro do administrador continua sendo um [comando explícito](../ADMINISTRADOR.md), separado da inicialização.

Nesta etapa não foram executados migrations, importação SQL, cadastro/conversão de administrador ou alterações nos serviços, volumes e dados existentes.

### Verificação executada

De `backend`, com as dependências já instaladas, foi executado:

```bash
env MYSQL_TEST_URL= MYSQL_TEST_ALLOW_RESET= .venv/bin/python -m pytest -q \
  tests/unit tests/contract/test_swagger.py \
  tests/integration/test_operational_improvements.py \
  -k 'not stalled_handshake'
.venv/bin/python -m ruff check src tests scripts
.venv/bin/python -m pip check
```

Resultado: **34 testes passaram**, um teste de handshake SQL foi desmarcado pelo filtro, Ruff aprovado e dependências consistentes. Houve um aviso de depreciação já existente no TestClient da combinação Starlette/httpx; não foi adicionado pacote para contorná-lo. Os testes executados não usam um servidor MySQL nem demonstram que a conexão real está disponível.

Os novos testes estão em [`test_settings.py`](../tests/unit/test_settings.py) e [`test_startup.py`](../tests/unit/test_startup.py). Cobrem configuração ausente/incompleta, driver e porta, precedência de variáveis, parâmetros reservados, erro sem credenciais e startup sem conexão ou cadastros.
